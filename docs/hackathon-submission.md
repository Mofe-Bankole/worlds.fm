## What they are asking for

The framing is explicit: *"Agents are getting smarter, but they're culturally
blind. They can reason, plan, and execute — but ask them what to recommend, what
to build, or what people actually want, and they're guessing."*

Build an agentic tool, an agent-powered app, or wire Qloo into an existing agent,
using the taste graph (250M+ entities) so the result *"can do more than 'answer
well'"*.

Two sentences decide whether an entry is even aimed correctly:

> "We're not looking for demos of what LLMs can already do."

> "If your submission would work the same without Qloo, you're building the wrong
> thing."

The second one is the sharpest constraint in the brief. It rules out an LLM
feature bolted onto a Qloo page, and it rules out a Qloo page with an LLM
narration. The dependency has to run both ways.

## Judging criteria

| Criterion | What it asks | What that means here |
|---|---|---|
| **Technological Implementation** | How thoroughly and skilfully does it use Qloo? Genuine effort, non-trivial working implementation? | Qloo must *drive* the agent, not decorate it. Depth of integration is scored. |
| **Design** | A complete, coherent product experience, not a technical proof of concept. | The agent must land as a product surface, not a chat box beside the app. |
| **Potential Impact** | A credible, specific case for a real problem for a real audience — and does the demo actually address it? | The claim must be demonstrated, not asserted. |
| **Quality of the Idea** | Creative, non-obvious use of Qloo; genuine understanding of the space. | Using an agent to **verify** rather than to generate is the non-obvious move. |

## The gap that matters

Requirements 2 and 5 are mechanical. The substantive gap was the brief itself:
**the submission must be agentic, and Worlds.fm had no agent.**

What existed was a deterministic graph: Qloo returns affinities, a resolver
labels each edge with the strongest basis it can support, and the UI shows it.
There was no LLM, no agent loop and no tool use anywhere in `apps/api` or
`apps/web`. `README.md` described the hosted LLM as *"optional"* and *"never a
required dependency for the initial journey"* — a reasonable product stance, and
in direct tension with the event being judged.

The fix was not to add an LLM feature. It was to build the one capability the
existing design was already shaped around and never had an actor for: an agent
that takes two nodes and establishes whether a **real, sourced** connection
between them exists. `AGENTS.md` §12 defines it;
[`backend/connection-agent.md`](./backend/connection-agent.md) designs it.

**State: the precomputed findings are live, but they are not generated by a
running hosted AI agent.** Bob Marley's world now shows
four `documented` edges with working citations, and Tame Impala's shows one.
A provider-neutral offline tool-use runner and Factory SDK model adapter are
fixture-tested. Bounded authenticated Qloo/Factory research was attempted
locally, including Clams Casino on 27 October; none produced a finding.
Human approval of a resulting finding is still missing. No provider is needed
to *display the existing static corpus*; a successful model-backed run is
needed to demonstrate the agent's research contribution.

For a convincing *"would this work the same without Qloo?"* answer, demonstrate
the executable runner selecting a real Qloo-ranked pair that a plain artist
lookup would not have selected. The existing family/member citations do not
prove this on their own. Stage-one agentic eligibility remains at risk.

### The honest gap that remains

The findings are verified against **live MusicBrainz output**, which is machine
verification, not editorial review. A human should read the statements against
their sources before the "sourced facts" claim is presented as signed off. The
same caveat already applies to the featured-world facts.
